# 1shot 사용 설명서

짧은 소개는 [README](../README.md)에 있습니다.

## 설치

```bash
brew install --cask itdar/tap/1shot
```

- `/Applications/1shot.app`(관리 UI)과 `1shot` 명령이 설치됩니다.
- 요구 사항: Apple Silicon, macOS 14 이상
- Developer ID로 서명하고 Apple 공증(notarization)을 받았습니다.
- 비밀번호와 항목은 **앱 전용 보안 키체인**에 저장합니다. 다른 프로그램은 읽거나 바꿀 수 없습니다. 설정에서 **iCloud 키체인 동기화**를 켤 수 있습니다.
- 손쉬운 사용 권한은 `1shot fill`을 실행하는 앱(Terminal, iTerm, 에이전트 실행 앱)에 필요합니다. 설정 위치: 시스템 설정 > 개인정보 보호 및 보안 > 손쉬운 사용

**직접 다운로드:** [Releases](https://github.com/itdar/1shot-dist/releases/latest)에서 `1shot-<버전>.dmg`를 받으세요.

1. dmg를 열고 `1shot.app`을 `Applications`로 끌어 놓습니다.
2. 앱을 엽니다. 공증받은 앱이라 경고 없이 열립니다.
3. 앱 왼쪽 아래의 **터미널 명령 설치**를 누릅니다. `/opt/homebrew/bin`(쓰기 가능할 때) 또는 `/usr/local/bin`(관리자 암호 필요)에 `1shot` 링크를 만듭니다.

확인:

```bash
1shot doctor
```

소스에서 빌드하려면 `./install.sh`를 실행하세요. 이 스크립트는 CLI만 `~/.local/bin/1shot`에 설치합니다. 코드 서명 인증서가 필요합니다(Xcode에 Apple ID로 한 번 로그인하면 생깁니다). 소스 빌드는 앱 전용 키체인 권한이 없어서 로그인 키체인과 서명된 항목 파일을 씁니다([SECURITY.md](../SECURITY.md) 참고).

이전 버전(0.4 이하)에서 올리면 앱에 "이전 버전의 데이터" 배너가 뜹니다. **옮기기…**를 누르거나 `1shot migrate`를 실행하세요.

## 관리 UI

`1shot.app`을 여세요. 메뉴 막대의 열쇠 아이콘에서도 열 수 있습니다. Spotlight에서는 `1shot`, `원샷`, `1샷`, `1tit`(한글 자판을 영문 상태로 친 1샷)으로 찾을 수 있습니다(앱을 한 번 실행한 뒤). `install.sh`로 CLI만 설치하면 앱이 없으므로 Spotlight에 나오지 않습니다.

- 항목 추가, 수정, 삭제
- 대상 선택: 앱(실행 중인 앱 목록에서 고를 수 있음), 웹 도메인, 또는 둘 다
- 비밀번호 저장과 삭제. UI는 저장한 값을 다시 보여 주지 않습니다.
- 인증 모드, 칸 종류 검사, 앱 서명 확인(Team ID 자동 채움)
- 정보 창, 업데이트 확인, 로그인 시 실행, 첫 실행 안내, 설정 백업/복원, 모든 데이터 삭제, 기기 간 동기화
- 한국어와 영어 (시스템 언어를 따릅니다)
- 에이전트가 실행할 명령 복사
- **칸 옆 1shot 버튼**: 브라우저의 로그인 칸 옆에 붙습니다. 저장된 사이트는 **⇧⌘1 입력 │ ⇧⌘2 수정**, 없는 사이트는 **⇧⌘1 저장**으로 나옵니다. 아이디 칸이라도 옆에 비밀번호 칸이 있으면 나옵니다.
- **로그인 실패 확인**: 입력한 뒤 90초 안에 같은 로그인 칸에서 ⇧⌘1을 다시 누르면 "방금 로그인이 안 됐나요?" 메뉴가 뜹니다. 비밀번호 바꾸기 또는 다시 입력을 고릅니다.
- **단축키 하나** ⌥⌘1: 칸에 맞게 아이디나 비밀번호를 입력하고, 항목이 없으면 저장 창을 엽니다. 설정에서 바꿀 수 있습니다. 개별 단축키는 설정의 "고급 단축키"에 있습니다(기본 꺼짐).
  - 누르면 지금 화면(앱, 웹 도메인)에 맞는 항목을 찾아서 입력합니다. 가장 구체적인 항목(앱 + 도메인 > 하나만)이 이깁니다.
  - 맞는 항목이 없거나 같은 수준으로 여러 개면 입력하지 않고 경고음을 냅니다. 결과는 메뉴와 설정 창에 보입니다.
  - 단축키를 쓰려면 **1shot.app**에 손쉬운 사용 권한이 필요합니다(설정 창의 "권한 요청…").

## 사용

**1. 항목을 만듭니다.** 가장 쉬운 방법: 로그인 페이지를 열고 다음을 실행한 뒤 3초 안에 아이디 칸을 클릭하세요. 앱, 도메인, 코드 서명을 읽어서 항목을 만들고, 비밀번호를 묻습니다.

```bash
1shot new
```

앱에서는 칸 옆의 **1shot에 저장** 버튼을 쓰는 것이 가장 쉽습니다. 직접 적으려면 UI나 `~/.config/1shot/entries.yaml`(소스 빌드)을 씁니다. 비밀번호는 넣지 않습니다.

```yaml
entries:
  - id: battlenet
    match: { app: net.battle.app, team: G847MC6JZ5, domain: account.battle.net }  # 번들 ID만 씁니다. 앱 항목은 team이 꼭 필요합니다
    user: me@example.com
    auth: none                       # none | biometric | password
    field_check: false               # Battle.net(CEF)은 칸 종류를 알려 주지 않습니다
  - id: naver
    match: { domain: nid.naver.com } # 정확히 같은 호스트만, https만, 알려진 브라우저에서만
    user: myid
    auth: biometric
```

**2. 비밀번호를 저장합니다.** 사람이 UI나 터미널에서 직접 입력합니다. 화면에 표시되지 않습니다.

```bash
1shot add naver
```

2단계 인증 코드(TOTP)도 쓰려면 인증 앱에 등록할 때 받은 비밀값(또는 `otpauth://` URI)을 저장합니다.

```bash
1shot add naver --otp
```

**3. 입력합니다.** 에이전트가 실행할 명령입니다. 먼저 해당 칸을 클릭하세요. `auto`는 지금 화면에 맞는 항목을 스스로 찾습니다.

```bash
1shot auto user
1shot auto pass
1shot auto otp
```

**4. 에이전트를 연결합니다 (Claude Code).** skill과 권한 규칙을 설치합니다. 에이전트는 `auto`, `fill`, `check`만 쓸 수 있고, 설정을 바꾸는 명령과 설정·기록 파일 쓰기는 거부됩니다.

```bash
1shot agent claude --dry-run   # 바뀔 내용만 봅니다
1shot agent claude
```

| 명령 | 동작 |
|---|---|
| `1shot add <id> [--stdin] [--otp]` | 비밀번호(또는 `--otp`: TOTP 비밀값)를 키체인에 저장합니다 (인증 필요) |
| `1shot auto user\|pass\|otp` | 지금 화면에 맞는 항목을 찾아서 입력합니다. 에이전트와 단축키가 씁니다 |
| `1shot fill <id> user\|pass\|otp` | 정한 항목으로 검사, 인증, 입력을 합니다 |
| `1shot check <id> [user\|pass\|otp]` | 검사만 합니다. 입력하지 않습니다 |
| `1shot capture [--wait N]` | 지금 포커스(앱, 서명, 페이지, 칸 종류)와 추천 항목을 JSON으로 보여 줍니다 |
| `1shot new [<id>] [--wait N] [--user U]` | 지금 포커스로 항목을 만들고 비밀번호를 받습니다 (인증 필요) |
| `1shot log [-n N] [--json]` | 입력 기록과 무결성 검사 결과를 보여 줍니다 |
| `1shot log --clear` | 입력 기록을 모두 지웁니다 (인증 필요) |
| `1shot agent claude [--dry-run]` | Claude Code skill과 권한 규칙을 설치합니다 |
| `1shot info list \| fill <id> \| get <id>` | 개인정보 목록, 입력, 읽기 (아래 참고) |
| `1shot info set <id> \| rm <id>` | 개인정보 저장과 삭제 (인증 필요) |
| `1shot list` | 항목, 저장 여부, 보호 수준을 보여 줍니다 |
| `1shot rm <id>` | 항목, 비밀번호, 인증 코드 비밀을 한 번에 지웁니다 (인증 1번) |
| `1shot rm <id> --password` / `--otp` | 그 비밀만 지우고 항목은 남깁니다 (인증 필요) |
| `1shot doctor` | 권한 상태와 현재 포커스 정보를 보여 줍니다 |
| `1shot export` / `1shot import [--yaml]` | 항목을 읽고 씁니다 (UI가 씁니다, 비밀번호 없음). import는 인증이 필요합니다 |
| `1shot config approve` | 밖에서 고친 항목 파일을 승인합니다 (인증 필요) |
| `1shot config rekey` | 서명 키를 새로 만들고 다시 서명합니다 (인증 필요) |
| `1shot sync setup <폴더> \| push \| pull \| status \| off` | 기기 간 동기화 (아래 참고) |
| `1shot store status` / `1shot store icloud on\|off` | 저장 위치와 iCloud 키체인 동기화 (인증 필요) |
| `1shot migrate` | 이전 버전 데이터를 보안 키체인으로 옮깁니다 (인증 필요) |
| `1shot reset` | 비밀번호, 내부 키, 항목 파일을 모두 지웁니다 (인증 필요) |

"인증 필요"는 Touch ID 또는 맥 암호입니다. 에이전트는 이 단계를 통과할 수 없습니다. 그래서 에이전트는 설정을 바꾸거나 비밀번호를 다른 곳으로 보낼 수 없습니다.

### 항목 옵션

| 키 | 뜻 |
|---|---|
| `match.app` | 맨 앞 앱의 번들 ID. 앱 이름은 비교하지 않습니다. `{mac: ..., win: ...}`도 됩니다 |
| `match.team` | 앱의 코드 서명 Team ID, 또는 Apple 앱이면 `apple`. 위장 앱을 막습니다. **앱 항목에는 필수입니다** (없으면 입력을 거부합니다) |
| `match.domain` | 포커스된 칸이 든 페이지의 정확한 호스트. `match.app`이 없으면 알려진 브라우저(Safari, Chrome, Edge, Firefox, Brave, Arc)에서만 입력합니다 |
| `match.path` | 페이지 경로 제한 (예: `/login`) |
| `user` | 아이디 |
| `auth` | `none` · `biometric` · `password` |
| `field_check` | 칸 종류 검사 (기본 `true`) |
| `submit` | 비밀번호 입력 후 Return을 누릅니다 (기본 `false`) |

## 저장하며 입력

브라우저 확장 없이, 로그인할 때 바로 저장합니다.

1. 1shot에 없는 사이트의 비밀번호 칸을 누르면 칸 옆에 **1shot에 저장** 버튼이 붙습니다.
2. 버튼(또는 ⌥⌘1)을 누르면 칸 아래에 작은 창이 뜹니다. 사이트 대신 이 창에 아이디와 비밀번호를 치고 Return을 누릅니다.
3. Touch ID 뒤에 1shot이 저장하고, 페이지에 대신 입력합니다.

- 회원가입: **강한 비밀번호 만들기**를 고르면 1shot이 만들어서 저장하고 입력합니다(확인 칸까지).
- 비밀번호가 바뀌었으면 같은 창에서 **저장된 비밀번호 바꾸기**를 고릅니다.
- macOS는 다른 앱이 사이트의 비밀번호 칸에 치는 값을 읽지 못하게 막습니다. 그래서 1shot은 사용자가 사이트에 직접 친 값을 저장하지 않고, 1shot 창에 친 값만 저장합니다.

## 다른 앱에서 가져오기

앱의 **다른 앱에서 로그인 가져오기…**에서 Chrome, Edge, Safari/암호 앱, Firefox, 1Password, Bitwarden이 내보낸 CSV 파일을 고르세요. 목록을 확인하고 고른 뒤 Touch ID 한 번으로 가져옵니다. CSV 파일에는 비밀번호가 그대로 들어 있으니, 가져온 뒤 지우세요(앱이 휴지통으로 보낼지 묻습니다).

## 개인정보 (양식 채우기)

주소, 전화번호, 학력, 경력, 자격증처럼 공개되면 곤란한 정보를 저장합니다. 에이전트는 **목록만** 봅니다. 값을 볼 수 있는지는 항목마다 정합니다.

```bash
1shot info set addr --label "집 주소" --domain www.applyhome.co.kr   # 값은 터미널에서 묻습니다 (화면에 보이지 않음)
1shot info set career --label "경력 요약" --reveal allow --stdin < career.txt
1shot info list           # 에이전트용: id, 이름, 종류, 규칙만
1shot info auto           # 에이전트용: 칸의 이름표를 읽고 맞는 항목(과 조각)을 골라 입력
1shot info fill addr      # 에이전트용: 포커스된 칸에 입력
1shot info get career     # 에이전트용: allow 항목만 출력 (ask는 Touch ID 뒤)
1shot info get            # 에이전트용: allow 항목 전체를 JSON 하나로 출력
```

| `reveal` | 에이전트 | 쓰임 |
|---|---|---|
| `type` (기본) | 값을 볼 수 없음. `info fill`로 입력만 | 주소, 전화번호, 생년월일 |
| `ask` | Touch ID 승인 뒤 `info get` | 가족 사항 |
| `allow` | `info get`으로 읽음 | 경력, 자격증 (자기소개서 작성) |

- 입력 대상: 알려진 브라우저의 https 페이지에 있는 텍스트 칸, 비밀번호 칸, 목록(`select`), 라디오 버튼, 체크 박스. 날짜 선택기(`type=date`)는 지원하지 않습니다.
- 목록: 1shot이 값을 입력해 옵션을 고르고, 고른 옵션이 값과 같은지 확인합니다. `03`과 `3월`처럼 숫자가 같으면 같은 값으로 봅니다.
- 라디오 버튼: 값과 같은 이름의 버튼을 누릅니다. 체크 박스: 값이 `예`/`yes`/`1`이면 켜고, `아니오`/`no`/`0`이면 끕니다.
- `--domain`을 정하면 그 사이트에만 승인 없이 입력합니다. 정하지 않으면 입력할 때마다 사이트 이름이 적힌 Touch ID 창이 뜹니다.
- 일반 텍스트 칸에 입력한 값은 화면에 보입니다. 화면을 볼 수 있는 에이전트는 입력 뒤에 읽을 수 있습니다([SECURITY.md](../SECURITY.md) 남은 위험 10).
- 앱의 **개인정보** 화면에서도 관리합니다.

### 조각과 형식 (`--part`, `--format`)

값의 종류(`kind`)가 조각을 정합니다. 종류를 정하지 않으면 id와 이름으로 추측합니다(`phone`, `birth`, "주민등록번호" 등). `1shot info set <id> --kind phone`으로 정할 수 있습니다.

| `kind` | 조각 | 예 (값 `010-1234-5678`, `1990-01-02`, `900102-1234567`) |
|---|---|---|
| `phone` | 3개 | `--part 2` → `1234` |
| `date` | 3개 (년, 월, 일) | `--part 2` → `01`, `--part 2 --format nozero` → `1` |
| `rrn` | 2개 (앞 6자리, 뒤 7자리) | `--part 2` → 뒤 7자리 (비밀번호 칸에도 입력) |
| `text` | `-` `.` `/` 공백으로 나눈 조각 | |

`--format`: `digits`(숫자만), `dash`, `dot`, `slash`, `space`, `plain`(구분 없음), `nozero`(앞의 0 빼기). 쉼표로 여러 개를 씁니다. 예: `1shot info fill birth --format dot,nozero` → `1990.1.2`.

### `info auto`

에이전트가 칸을 누르고 `1shot info auto`를 실행합니다. 1shot이 칸의 이름표, 설명, placeholder, 앞의 글자, 표 머리글, 요소 id를 읽고 항목을 고릅니다.

- `[010] - [1234] - [5678]`처럼 기호만 사이에 둔 칸 줄은 위치로 조각을 고릅니다. `[1990]년 [1]월 [2]일`도 같습니다.
- "가운데 자리", "뒷자리", "연도" 같은 말이나 `hp2` 같은 id 숫자로도 조각을 고릅니다.
- placeholder가 `YYYY.MM.DD`, `010-0000-0000`, "'-' 없이 숫자만"이면 그 형식으로 입력합니다.
- 맞는 항목이 없거나 둘 이상이면 입력하지 않고 `fail: <이유>`와 후보를 돌려줍니다. 에이전트는 `info fill <id>`로 고릅니다.
- `--dry-run`: 입력하지 않고 고른 결과만 보여 줍니다.

브라우저가 `autocomplete`, `name`, `maxlength` 속성을 접근성 API로 알려 주지 않으므로 1shot은 이 속성을 쓰지 않습니다.

## 기기 간 동기화

**같은 Apple ID의 맥끼리:** 첫 실행 안내나 설정 > 저장 위치에서 **iCloud 키체인으로 동기화**를 켜면 끝입니다.

**그 밖의 경우:** 설정 > 기기 간 동기화의 마법사를 쓰세요. 첫 맥에서 **새로 시작**(폴더 선택, 복구 코드 보관), 다른 맥에서 **참여**(같은 폴더, 복구 코드)를 누릅니다. 그 뒤로는 자동으로 올리고 받습니다.

명령으로 할 때: 암호화한 보관 파일(`1shot-vault.age`) 하나를 공유 폴더에 둡니다. 폴더는 git 저장소, iCloud Drive, Dropbox, Syncthing 등 무엇이든 됩니다. 폴더가 git 저장소이면 pull, commit, push를 자동으로 합니다.

```bash
1shot sync setup ~/Library/Mobile\ Documents/com~apple~CloudDocs/1shot   # 기기마다 한 번, 같은 동기화 암호
1shot sync push    # 이 기기의 항목과 비밀번호를 보관 파일로
1shot sync pull    # 보관 파일을 이 기기로
```

- 암호화: age (scrypt). 동기화 암호는 12자 이상이어야 합니다.
- push와 pull은 인증이 필요합니다. 인증 창에 대상 폴더가 표시됩니다.
- 다른 기기가 마지막 pull 뒤에 보관 파일을 바꿨으면 push를 거부합니다(`--force`로 덮어쓰기).
- 앱의 설정 > 기기 간 동기화에서도 할 수 있습니다.

## 동기화 방법 비교

| 방법 | 대상 | 설정 |
|---|---|---|
| iCloud 키체인 | 같은 Apple 계정의 Mac | 설정 > 저장 위치 > iCloud 키체인으로 동기화 |
| 암호화 보관 파일 | git, iCloud Drive, Dropbox 등 아무 폴더 (다른 계정, 다른 OS 포함) | `1shot sync setup <폴더>` |

## 보호 수준 (macOS)

| `auth` | 입력할 때 | 에이전트가 `security` 명령으로 직접 읽기 |
|---|---|---|
| `none` | 인증 없이 입력합니다 | 막힘 (키체인 암호 창이 뜸) |
| `biometric` | Touch ID 인증 후 입력합니다 | 막힘 |
| `password` | Touch ID 또는 맥 암호 인증 후 입력합니다 | 막힘 |

## `fill` 순서

1. 단축키의 수정 키(⌃⌥⌘ 등)를 뗄 때까지 기다립니다.
2. 맨 앞 앱의 번들 ID가 `match.app`과 같은지 확인합니다.
3. 포커스된 칸이 들어 있는 웹 페이지(또는 iframe)의 URL이 `match.domain`과 같은지 확인합니다.
4. 코드 서명을 확인합니다. `match.team`이 있으면 그 팀, 도메인만 있는 항목이면 알려진 브라우저의 팀이어야 합니다.
5. 칸 종류를 확인합니다. `pass`는 비밀번호 칸에만, `user`는 텍스트 칸에만, `otp`는 텍스트나 비밀번호 칸에만 입력합니다.
6. `auth` 설정에 따라 인증합니다 (`pass`, `otp`).
7. 키체인에서 값을 읽습니다. 사용자 상호작용은 끈 상태로 읽습니다.
8. 2번부터 5번까지 다시 확인합니다. 인증 창 때문에 포커스가 바뀔 수 있기 때문입니다.
9. 포커스된 칸을 잠그고 입력합니다. 글자마다 같은 칸인지 확인하고, 다른 앱으로 바뀌면 멈춥니다. 메모리에 있는 값을 지웁니다.
10. 결과를 입력 기록에 남깁니다.

## 한계

- 같은 사용자 계정의 악성 프로그램은 완전히 막지 못합니다. 이 도구는 사고를 막는 장치입니다.
- 항목 파일은 서명되어 있습니다. 밖에서 고치면 승인할 때까지 1shot이 입력하지 않습니다. 그래도 에이전트에게 `~/.config/1shot/` 쓰기 권한은 주지 않는 것이 좋습니다.
- 손쉬운 사용 API로 칸 정보를 주지 않는 앱도 있습니다. 그런 앱에서는 `field_check: false`를 설정하세요. 이 경우 칸 종류를 검사하지 않습니다.
- 안티치트 프로그램은 가짜 키 입력을 거부할 수 있습니다.
- Windows는 아직 지원하지 않습니다. 계획은 `PLAN.md`에 있습니다.
